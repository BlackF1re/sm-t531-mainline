# Возможности сна SM-T531 и сверка с Android

Аудит 2026-11-03. Тесты автономности и чтение заряда/тока не выполняются.
Машиночитаемая проекция трёх DTB: [sleep-capabilities-20261103.json](sleep-capabilities-20261103.json).
Её создаёт `tools/inspect-power-topology.py` (python3-libfdt); инструмент
читает файлы DTB, не обращается к оборудованию. Описание режима в DT
подтверждает конфигурацию, но не его фактическое использование.

Сравниваются сохранённый живой DT Android, текущий Linux `unified2`
и подготовленный DT кандидата `sleep1`. Сохранённый Android — Dirty Unicorns
6.0.1 с downstream-ядром 3.4, **не чистая заводская прошивка Samsung**.
Совпадение его бинарного ядра с отдельно исследуемым исходным деревом
Samsung/Lineage не установлено. Короткая проверка Android завершена: при
отключённом USB системный сон и пробуждение через 8,137 с прошли успешно.
С подключённым USB контроллер возвращал `-EBUSY`. Счётчики XO/VMIN
не выросли даже в Android; журнал показывает удержанные такты MDSS
и обычные XO/GPLL0 votes. Поэтому успешный CPU collapse нельзя считать
подтверждением самого глубокого сна SoC.

| Уровень | Что происходит и когда применять | Состояние порта перед новой проверкой Android |
|---|---|---|
| CPU WFI | Ядро ждёт прерывания; минимальная задержка, короткие паузы во время работы | Доступен на четырёх CPU, счётчики растут |
| CPU standalone collapse | Отдельное ядро отключается, контекст восстанавливается через secure firmware; более длинные паузы | CPUidle `cpu-spc` включён, счётчики растут |
| Согласованный CPU collapse | Последнее ядро согласует более глубокий сон кластера и RPM | Есть отдельный путь системного сна в кандидате; согласованного cluster CPUidle governor нет |
| L2 retention | Содержимое L2 сохраняется; быстрое восстановление | Короткие функциональные проверки ранее прошли, итоговая матрица не закрыта |
| L2 GDHS | Отдельная аппаратная последовательность отключения/восстановления L2 | Есть в downstream DT и в кандидате; требуется итоговая функциональная проверка |
| APC/L2 collapse без RPM | CPU и L2 теряют состояние, программное восстановление без полного согласования сна SoC | Реализован; это не доказательство выключения XO |
| APC/L2 collapse с RPM | Последний CPU передаёт RPM таблицу пробуждений MPM и использует RPM-последовательность SAW | Возврат с удерживаемым PHY ранее работал; при полном освобождении PHY остаётся сбой |
| XO shutdown | RPM выключает общий опорный генератор, когда это разрешают все потребители | Успешными циклами порта пока не подтверждён |
| VMIN | RPM снижает общие напряжения до допустимого уровня сна | Успешными циклами порта пока не подтверждён |
| Runtime PM / GDSC | Отдельные устройства и локальные домены отключаются даже без сна всей системы | Камера, JPEG, Venus и HSIC в текущем снимке выключены; MDSS и GPU включены при работающем интерфейсе |
| `s2idle` | Ядро замораживает задачи и приостанавливает устройства, CPU используют доступные idle states | Ранее проверен с восстановлением интерфейса; временный системный режим по умолчанию |
| `shallow` / standby | Платформенный неглубокий сон, без обязательного полного отключения SoC | Есть отдельный путь L2 retention + WFI |
| Hibernation | RAM сохраняется на накопитель, последующая загрузка восстанавливает образ | Не включена; не заменяет телефонный standby с событиями пробуждения |

Downstream DT задаёт CPU WFI/SPC/PC с policy latency 1/500/550 мкс;
L2 GDHS/PC-no-RPM/PC-RPM — 700/1000/12700 мкс. Это параметры выбора,
а не измеренные задержки. CPU retention встречается в общем vendor API,
но отдельного такого состояния в таблице CPU этого планшета нет.
Нельзя объявлять все режимы других Snapdragon поддерживаемыми SM-T531.

## Домены, напряжения и тактирование

* **APC / CPU и L2:** SAW/SPM управляет локальными переходами, SCM/TZ —
  передачей управления и warm resume. Это не обычный локальный GDSC.
* **CX:** RPM `smpa1`, запрос уровня производительности. В живом `unified2`
  CPU ссылаются на обычный CX (индекс 0); в кандидате — CX active-only
  (индекс 1). В `rpmpd` обычный домен голосует уровнем и для active,
  и для sleep; active-only передаёт нулевой sleep corner после синхронизации.
  Это подтверждённое различие конфигурации, не доказательство причины сбоя.
* **MX:** downstream CPR использует PM8226 L3 active-only, отдельно имеется
  sleep-only L3. Linux SAW также ссылается на L3. Разные имена DT сами
  по себе не доказывают неправильный sleep vote: `qcom_smd-regulator`
  текущего Linux пишет только ACTIVE_STATE. Нужно сравнить реальные запросы
  и унаследованные sleep-настройки, а не механически менять phandle.
* **Локальные GDSC:** downstream живой DT включает MDSS, OXILI_CX,
  Venus, VFE, JPEG и USB HSIC. OXILI_GX и ряд шаблонных доменов отключены.
  Поэтому отсутствие отдельного OXILI_GX в mainline MSM8226 нельзя
  автоматически считать пробелом. Linux предоставляет соответствующие
  MDSS/OXILI_CX/Venus/VFE/JPEG и HSIC домены.
* **XO/PLL/шины:** отключение GDSC не снимает автоматически запросы XO,
  DSI PHY, USB, interconnect и firmware сопроцессоров. В downstream
  MPM дополнительно удерживает XO при недоступном для MPM источнике
  пробуждения; при входе во сне пересчитывает это разрешение.

В downstream RPM перед последним CPU отправляет накопленные sleep-запросы
и маскирует приёмное SMD-прерывание; затем MPM получает таблицу и deadline.
Linux передаёт resource votes иначе, поэтому отсутствие функции с тем же
именем ещё не доказывает отсутствие протокола. Сопоставлять нужно порядок,
ACK, маски пробуждения и фактическое восстановление.

## Сохранность загрузки и отдельная исправленная проблема

Перед переключением свежая полная копия внутреннего BOOT (10 МиБ)
совпала с ранее проверенной копией. Свежая вычитка через lk2nd двух
виртуальных частей также воспроизвела полный BOOT. При установке Android
изменён только payload после первых 512 КиБ; lk2nd prefix проверен обратно
и не изменился. Возврат завершён и проверен по SHA-256 всего физического BOOT;
подробности ниже.

Во время исходного аудита `CONFIG_SYSCON_REBOOT_MODE` был выключен:
команда bootloader привела к обычной загрузке, в lk2nd вошли физической
кнопкой. Драйвер добавлен в `config/kernel.fragment` и включён в новую
сборку; передача команды bootloader на ней отдельно не проверялась.

Задержка Plasma после DRM устранена в проверенной обычной перезагрузке:
после замены вложенного `ExecStartPost=systemctl` на зависимость `Wants`
служба стала active на 31,497 с вместо 236,976 с, SDDM активен. Это
отдельный результат запуска, не закрытие проблемы глубокого сна.

через Heimdall из Samsung Download Mode без переразметки. После загрузки
Linux SHA-256 физического `/dev/mmcblk0p14` совпал с резервной копией:
`f2e67d637182e79193912952f45341ceac4e621aeb7cefab4a8e55a6663192fc`.
