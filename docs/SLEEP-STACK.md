# Сон SM-T531: устройство и выбор режима

Текущая квалификация восстановления GPU-памяти: [OCMEM resume](OCMEM-RESUME-20261103.md).
Ниже приведены также исторические эксперименты; они не входят в основную серию.

Платформа MSM8226 не имеет одного универсального «глубокого сна». Есть
независимые уровни: простой отдельного CPU, состояние общего L2, системный
suspend, автономная работа WCNSS и решения RPM о питании/тактах всей SoC.
Отключение экрана само по себе не гарантирует suspend.

## Режимы

| Режим | Что происходит | Когда использовать |
| --- | --- | --- |
| CPU WFI | Ядро прекращает выполнение до прерывания; контекст остаётся на месте. | Автоматически, между задачами во время обычной работы. |
| CPU standalone power collapse (SPC) | Отключается питание отдельного CPU; Linux сохраняет и восстанавливает его контекст. | Автоматически через cpuidle при достаточно длинном простое. |
| `s2idle` | Linux замораживает приложения и приостанавливает устройства, CPU используют cpuidle. Общий L2 не переводится отдельным системным вызовом в collapse. | Совместимость, диагностика источников пробуждения, запасной режим. |
| `shallow` | Вторичные CPU отключаются; основной ждёт прерывания, L2 находится в retention. | Проверка suspend устройств и быстрого возврата без полного collapse кластера. |
| `deep` + retention | Основной CPU тоже проходит collapse, L2 сохраняется. | Промежуточная аппаратная проверка и резервный вариант при проблемах с отключением L2. |
| `deep` + GDHS | Штатная последовательность gated head switch для общего L2 и соответствующий флаг SCM. Это промежуточное состояние между retention и полным collapse. | Диагностика и подбор политики платформы; приложения его не выбирают. |
| `deep` + standalone | CPU и L2 проходят collapse без RPM-handshake в последовательности SAW. | Резервный глубокий сон; сам по себе не доказывает сон всей SoC. |
| `deep` + RPM | MPM подготавливает маршруты пробуждения, затем SAW согласует collapse с RPM. RPM учитывает голоса остальных подсистем и выбирает допустимое состояние платформы. | Целевой обычный сон при погашенном экране, после подтверждения на устройстве. |
| Гибернация | Образ RAM записывается на накопитель, затем питание выключается. | В этой сборке отключена: восстановление образа для этой платы не реализовано и не проверено. |

`freeze` в `/sys/power/state` — прямой вход в suspend-to-idle. `standby` —
платформенный shallow. `mem` использует выбор `/sys/power/mem_sleep`.
Названия Linux не являются названиями дополнительных независимых блоков SoC.

XO shutdown, VMIN, снижение питания DDR и сохранение RAM — результат решений
RPM с учётом всех подсистем. Их нельзя честно считать включёнными только
потому, что Linux вернулся из `deep`: нужны счётчики APSS/RPM.
Самообновление DRAM сохраняет работающую систему; это не выключение планшета.

## Что реализовано в коде

* В производственном cmdline убран bring-up флаг `clk_ignore_unused`.
  Неиспользуемые линии тактирования теперь может отключать общий clock
  framework; критический CPU clock остаётся защищён `CLK_IS_CRITICAL`.
* Патчи 0133–0134 добавляют MPM, штатные последовательности L2 и CPU-голоса
  active-only. Подготовка MPM выполняется после отключения вторичных CPU;
  счётчики ссылок genpd вручную не меняются. Индексы начала последовательностей
  L2: retention 0, GDHS 4, standalone collapse 26, RPM collapse 54.
* Патч 0137 сообщает фактическую привязку GPIO IRQ к CPU общего TLMM
  interrupt, устраняя ложные попытки независимого переноса GPIO при hotplug.
* Патч 0139 убирает максимальные стартовые запросы RPM clocks из
  sleep-контекста MSM8226. Active handoff остаётся прежним; явные запросы
  реальных потребителей продолжают обрабатываться обычным драйвером.
* Патч 0138 сохраняет рабочие полосы CPU/GPU/MDP/OCMEM, но помечает
  запросы `RPM_ACTIVE_TAG`: рабочая полоса APSS не переносится в sleep-set.
* Эксперимент 0143 с полным unprepare интерфейсного такта DSI PHY
  исключён из рабочей серии; исходник сохранён в истории Git (`43648a2`).
  С ним `s2idle` и retention прошли, но RPM collapse не вернулся. Простое
  disable сохраняет prepare родителя и его RPM-запрос на XO; снятие этого
  запроса выявило незавершённую поддержку входа/возврата RPM collapse.
* Патч 0144 воспроизводит штатный wake-флаг IRQ возврата от RPM.
  Это исправление найденного отличия от Samsung, а не доказательство
  устранения всех проблем: короткие циклы вернули CPU, но последующая проверка
  пикселей выявила отдельную потерю OCMEM после RPM collapse.
* Патч 0148 восстанавливает существующий graphics lock OCMEM до возобновления
  GPU. Ручное восстановление этого диапазона устранило воспроизводимые нулевые
  пиксели после RPM collapse; проверка нового ядра описана в
  `OCMEM-RESUME-20261103.md`.
* Патч 0142 освобождает локальный bus clock MMSS в suspend_late,
  после приостановки GPU/MDP, и возвращает его в resume_early. RPM-запросы
  BIMC/OCMEM этим не меняются.
* Патч 0140 принудительно вызывает runtime suspend MDP5 на время
  системного сна. Перед возвратом scanout восстанавливаются такты,
  инициализация MDP/VBIF/CTL и сохранённая маска прерываний.
* Патч 0141 снимает запросы рабочих тактов USB после входа ChipIdea
  в PHY low-power. Опорный такт PHY возвращается в resume_early;
  sleep clock и питание PHY сохраняются.
* Патч 0136 восстанавливает таблицы занятости pipe/mixer/SMP при resume:
  сохранённые плоскости не должны использовать каналы, которые allocator
  ошибочно считает свободными.
* Патч 0135 управляет LCD через PM8226 GPIO2 с порядком reset/enable,
  подтверждённым исходным драйвером Samsung. Неизвестные отдельные линии
  питания моста не назначаются произвольным регуляторам; L5 остаётся включённым.
* `config/wcn36xx-standby.networkmanager.conf` включает энергосбережение Wi-Fi
  и WoWLAN ANY. WCNSS должен обрабатывать служебный трафик автономно; ANY
  допускает пробуждение по трафику. Это компромисс между доступностью и частотой
  пробуждений, а не обещание максимальной автономности в любой сети.
* `scripts/sleep-mode.sh` выбирает системную политику, не запускает сон и
  не проводит измерений батареи. Состояние L2 сохраняется через tmpfiles,
  системный режим — через sleep.conf.d.

Последовательности сопоставлены с
[исходниками Samsung MSM8226](https://github.com/LineageOS/android_kernel_samsung_msm8226/tree/3fa1853ed5d6c3a8ef5a2fda9822705243bbc256).
Промежуточные L2-режимы доступны для системного suspend; автоматический
координированный cluster-idle во время работающей системы этим изменением
не добавляется. Обычный cpuidle по-прежнему выбирает WFI/SPC отдельно для CPU.

## Управление

После установки скрипта как `/usr/local/sbin/t531-sleep-mode`:

```sh
t531-sleep-mode status
sudo t531-sleep-mode s2idle
# Экспертные варианты: shallow, retention, gdhs, standalone, rpm.
# Команда меняет политику; следующий обычный suspend её использует.
```

Нажатие питания и политика рабочего окружения должны использовать обычный
logind/systemd suspend. Не надо одновременно запускать собственный цикл
suspend в фоне: он будет снова усыплять планшет после ручного пробуждения.

[NetworkManager](https://github.com/NetworkManager/NetworkManager/blob/main/src/core/nm-manager.c)
намеренно пересоздаёт WoL-соединение после resume для
перепроверки доступности сети. Поэтому переподключение после resume само
по себе не доказывает потери ассоциации во сне. Доказательство WoWLAN —
входящий пакет, который будит систему до контрольного RTC-будильника.

Телефонный режим также требует отдельного рабочего модема и его wake IRQ.
Сон сам по себе не добавляет поддержку звонков/SMS. В текущем порте нельзя
обещать пробуждение по звонку без запуска и проверки модема.

Тесты автономности, времени работы от батареи и расхода заряда не проводятся
по указанию пользователя. Результат коротких функциональных проверок должен
быть зафиксирован отдельно; сборка кода не является доказательством resume.

## Текущее состояние проверки

Полный стек пока не принят. RPM не установлен режимом по умолчанию;
установленный `t531-sleep-mode` сохраняет `s2idle`.

* MDP5 с восстановлением регистров: контрольный RPM/L2 collapse успешен,
  изображение и реакция интерфейса подтверждены пользователем. В этом
  контрольном цикле XO shutdown не зафиксирован (Count=0).
* Эксперимент PHY с обычными callbacks: первый RPM-цикл не завершился,
  после перезагрузки сработал возврат к прежнему ядру.
* Эксперимент PHY с suspend_late/resume_early: `s2idle` успешен
  (13,817 секунды), пользователь подтвердил обе панели, реакцию интерфейса
  и отсутствие повторного гашения. `deep` + retention также успешен.
* RPM с этим же вариантом PHY не вернулся. Пользователь сообщил о ручной
  перезагрузке; автоматический reset этим сообщением не доказан. RAM-консоль
  заканчивается после отключения вторичных CPU, на
  `MSM8226: entering L2 sleep mode 3`; возврата из collapse нет.
* Ранее пользователь отметил исчезновение панелей после другого цикла.
  После загрузки обе панели созданы оболочкой и видны; после последнего
  успешного `s2idle` их видимость также подтверждена. Настройки оболочки
  для обхода этой проблемы не менялись.

Полное снятие запросов тактов пока нельзя считать исправлением глубокого
сна. Рабочий модуль на диске возвращён к варианту MDP5 с восстановлением
регистров, без экспериментального PHY clock PM. Следующие проверки должны
отдельно подтвердить возврат CPU из RPM collapse и увеличение счётчиков
XO/VMIN; успешный suspend со старым удерживаемым XO-запросом этого не доказывает.
Общий дамп регистров GCC через debugfs вызвал external abort в
`regmap_mmio_read32le` при чтении смещения `0x1c0`; это подтверждено
RAM-консолью после ручной перезагрузки. Этот способ диагностики больше
не используется. Архив сохранён отдельно от неудачных RPM-циклов.


### Контроль границы CPU/RPM с диагностикой 0145

На образе `bac90f227034` проверенный модуль MDP5/PHY (`566a65f1`)
вернулся из RPM collapse за 13,54 секунды. Отметки `SCM entry`,
`CPU resume reached, ret=0` и `voltage restore 0` присутствуют; счётчики
XO/VMIN остаются нулевыми. Экспериментальный модуль `52984341` на том же
образе не дошёл до отметки CPU resume, после чего произошла перезагрузка.
Происхождение reset пока не установлено.

Параметр экспериментального модуля `dsi_phy_sleep_gating=N` **не возвращает
прежний runtime PM**: он отключает только поздний системный callback.
Runtime suspend по-прежнему вызывает `clk_disable_unprepare`, снимая
удерживающий запрос родительского RPM clock. Поэтому этот цикл нельзя
считать контролем с гарантированно удерживаемым XO. Для настоящего
контроля восстановлен модуль `566a65f1`; повторный цикл успешен.
Отсутствие CPU resume локализует сбой раньше восстановления графики,
но само по себе не отличает потерю wake-события MPM от сбоя аппаратного
выхода из collapse. Эти варианты требуют раздельной проверки.

Диагностический кандидат 0146 добавляет выключенный по умолчанию таймер
vMPM с абсолютным сроком по физическому ARM architected counter — по
протоколу штатного ядра. Параметр `irq_qcom_mpm.legacy_timer_seconds`
ограничен 60 секундами, `0` сохраняет прежнее поведение. Это инструмент
разделения источников пробуждения, а не готовое исправление. Образ
`70c06d2ccd3a` собран и отправлен на пробную загрузку; до восстановления
связи результат загрузки и сна не подтверждён.

Проверка 0146 завершена: с проверенным модулем `566a65f1` система
проснулась за 7,994 секунды, IRQ MPM увеличился до 1, XO остался включён.
С модулем `52984341`, принудительно активным PHY перед suspend и
`dsi_phy_sleep_gating=Y`, тот же MPM-таймер (8 с) и резервный RTC (15 с)
не дали возврата CPU. После перезагрузки RAM-консоль заканчивается на
`SCM entry flags=0x1`; отметки `CPU resume reached` нет. Причина reset
не установлена. Это исключает объяснение только неправильным PMIC RTC,
но не доказывает конкретный дефект RPM/SAW/тактового восстановления.
Архив сохранён отдельно; модуль `566a65f1` возвращён на диск, запущено
прежнее ядро `unified2` через защитный загрузочный выбор. Новых циклов
в фоне нет. Полный стек всё ещё не принят.


### Ранняя диагностика возврата CPU

Диагностический кандидат 0147 (`sleep_trace=Y`, по умолчанию выключен)
временно направляет warm-entry CPU0 через короткий ARM trampoline.
Контрольный образ `d2999157123e` успешно проснулся за 13,795 секунды;
живая отметка IMEM дошла до `resume-completed`. Однако загрузчик
перезаписывает эту IMEM при перезагрузке: сохранность отметки не подтверждена,
использовать её после reset как доказательство нельзя.

Следующая диагностическая ревизия `1e1618b7a65b` записывает
`T531_WARM_ENTRY` также непосредственно в существующую RAM-консоль pstore,
до `cpu_resume_arm`. Код ограничен платой matisse3g, проверяет DT-разметку
ramoops и отсутствие ECC, затем в раннем коде проверяет сигнатуру и границы
кольцевого буфера. CPU1–3 уже отключены, IRQ выключены, параллельного
Linux console writer нет. Обычный warm-vector возвращается после цикла.
Это диагностический кандидат, а не принятый производственный патч.
Отсутствие этой строки после сбоя всё ещё не отличит отсутствие старта CPU
от невозможности первого чтения инструкций из DDR. Наличие строки,
напротив, докажет запуск раннего Linux warm-entry.

Образ `1e1618b7a65b` начал загрузку, чтение текущей RAM-консоли показало
0 ранних отметок. Проверка suspend на нём **не запускалась**: пользователь
видит чёрный экран с подсветкой, SSH аутентифицируется, но команды
не выполняются устойчиво. Поэтому это отдельная проблема загрузки,
а не доказанный сбой нового warm-entry trampoline. Подготовлено удаление
добавленного `ExecStartPre` раннего сбора диагностик из boot guard:
опциональный сбор не должен предшествовать выбору резервного ядра.
Для восстановления запрошена одна физическая перезагрузка; причинная
связь зависания с чтением RPM RAM ещё не установлена.

После физической перезагрузки загружено прежнее `unified2`, Plasma и SSH
восстановились. Ранний диагностический drop-in удалён, для `sleep1` на диске
восстановлен проверенный MSM `566a65f1`. В этой загрузке guard завершился
на 14,8 с, DRM был готов на 30,3 с, а native-graphics завершился только
на 237 с; logind тем временем сообщал тайм-ауты создания root user services.
Следовательно, четырёхминутную задержку этой загрузки нельзя приписывать
раннему сборщику. Вложенный `ExecStartPost=systemctl ... start display-manager`
заменён на `Wants=display-manager.service` с прежним `Before=` в исходной
и установленной службе. `systemd-analyze verify` прошёл, текущая сессия
не перезапускалась: SDDM активен, KWin/Plasma работают, оболочка сообщает
две панели, очереди systemd нет. Исчезновение задержки требует следующей
загрузки; точный механизм блокировки ещё не доказан. Новых циклов сна
и тестов автономности при этом не проводилось.


## Квалификация OCMEM после RPM collapse (2026-11-03)

Повторная серия с проверкой содержимого GPU-буферов отделила возврат CPU от
исправной графики. На предыдущем ядре пять режимов прошли, а RPM collapse
оставлял GMEM-отрисовку с нулевыми пикселями. Sysmem работал. Повтор штатного
SCM graphics lock для существующего диапазона OCMEM восстановил пиксели без
перезагрузки; один restore_sec_cfg и переустановка частоты этого не дали.

Патч 0148 переносит это восстановление в ранний resume драйвера OCMEM.
Новое ядро `7.2.9-t531-mainline-dirty` загружено с microSD, без изменения
внутреннего BOOT/lk2nd. Первый RPM-цикл с пиксельными проверками до и после
сна успешен без ручного вмешательства. Сбалансированная ревизия с парным unlock/lock прошла все шесть режимов
и кнопочный путь без ошибок фаз, затем пользователь подтвердил обе панели
и реакцию интерфейса. Слот принят; политика по умолчанию — s2idle.
Полные результаты текущей серии:
`OCMEM-RESUME-20261103.md` и `sleep-release-validation-20261103.json`.
Диагностические 0145–0147 и полное unprepare PHY 0143 в ядро не включены.

XO shutdown и VMIN по-прежнему требуют отдельного решения. Рабочий APSS
collapse не означает, что RPM отключил XO или снизил питание всей платформы.
Тестов автономности не проводилось. Стабильные 60 FPS этой правкой не доказаны.
