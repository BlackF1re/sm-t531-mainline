# Adreno 305B: hardware engines and memory

* **SOURCE/DEVICE:** GPU chip ID `0x03000512` (Adreno 305B, mainline `qcom,adreno-305.18`); this is the **3D GPU**, separate from the MDP5 display processor. The vendor GPU MMIO windows are `0xfdb00000+0x10000` (control) and `0xfdb20000+0x10000` (shader-memory aperture); the mainline GPU DT describes the first window. Interrupt GIC SPI33.
* **Command processor (CP):** one Linux DRM ring, PM4/ME and PFP microcode, indirect buffers, RPTR/WPTR, scratch/fence/IRQ; RBBM supplies clocks/busy/error/reset control. Mainline's chip-specific catalog selects `a330_pm4.fw` and `a330_pfp.fw` for ID `0x03000512`. Selection is source evidence; loaded firmware content/hash is a separate device fact.
* **A3xx engine register families:** VFD/PC/VPC (input/primitive stages), GRAS (rasterization), HLSQ and SP (shader scheduling/execution), TP (texturing), RB (render backend), UCHE (cache), VBIF (external memory interface), plus debug/performance counters. The register vocabulary establishes driver-visible functional units, **not** the exact number of shader lanes, texture pipes or physically working subunits of this specific silicon.
* **GMEM/OCMEM:** mainline A3xx catalog assigns **128 KiB GMEM** to `0x03000512`; the A305B driver allocates it through Qualcomm OCMEM, programs `RB_GMEM_BASE_ADDR` and must preserve the existing allocation/security lock across system sleep. MSM8226 OCMEM controller `0xfdd00000`, 128-KiB SRAM aperture `0xfec00000`. A registered `gmu_sram` DT label does not establish a separate GMU processor.
* **Power/data paths:** `OXILI_GFX3D_CLK`, OXILICX AHB/AXI clocks, OXILI CX/GX GDSCs, GPU ARM SMMU and VBIF→MMSS/DDR plus OCMEM interconnect votes. Only 19/200/320/450 MHz OPPs are board-described; 450 MHz under load, AXI 266.67 MHz and DDR 533.33 MHz were measured. Working clocks alone do not prove absence of bus/tiling stalls.
* **Driver-specific:** A305B VBIF port handling differs from other A3xx variants; the port's three-client fix, suspend drain, CP ring reconciliation and unsafe HLSQ read exclusions are documented in [gpu](gpu.md) and [gpu-smmu](gpu-smmu.md). A3xx hardware init sets UCHE 64-byte cacheline mode; that is a register configuration, not measured UCHE size.
* **Unresolved inventory:** shader/texture-unit counts, register-file/cache capacities other than GMEM, firmware runtime hashes, fault-recovery robustness, precise stall ownership, per-domain power draw and sustained graphics stability are **not** established by the catalog or the existing tests. Do not turn unverified hardware details into presumed throughput or performance tuning.
